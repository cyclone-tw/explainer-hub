一句話，和可以貼出去的那段

先講這兩週在試什麼，再拆開五個名字
可以貼到分享串：

這兩週我在試用 ORCA 把開發排開，最有感的有兩件。第一，我在用的 coding agent（會改程式的助手）各自登入帳號之後可以接到 ORCA；人在外面時，手機透過 Relay，就能遠端叫 Mac 或 Mac mini 上的 ORCA 繼續寫程式。第二，可以很快開出 worktree（工作桌）和 workspace（看板）。worktree 是同一個專案再開一張獨立工作桌，各寫各的分支，才不會一個人切換分支、另一個人的檔案跟著被換掉；workspace 是把這些工作桌放在同一塊看板上，方便我一起看。

另外走到要不要換做法的岔路，我會先請 Jev 判斷，再讓 Pi Agent 切路線。看不懂的程式，或是助手正在改什麼，就用 html-visualizer 畫成一頁我讀得懂的說明；要給人看，再用 cfdrop 丟一條大約一小時會消失的臨時連結。還在試，不是已經定下來的做法。

ORCA工作台
把助手接到同一塊看板。我人在外面，也能叫家裡的電腦繼續做。
手機走 Relay 連 Mac 或 Mac mini。同時進行的開發各開一張工作桌，避免搶同一份檔案。下面第 4 節展開這兩件。
Pi Agent動手
實際去讀程式、改檔案、跑指令的那個助手。
它是一套可以接不同模型的工具，名字本身不是某一家模型。
Jev判斷
岔路口的判斷：這一步要不要換、換到哪一條路線。
它回判斷，不自己改程式。這兩週我把它接在 Pi 的路線切換上。
html-visualizer說明頁
把「改了什麼、怎麼串」畫成一頁人看得懂的 HTML。
給我自己讀。不是投影片，也不是程式審查通過的證明。
cfdrop臨時連結
說明頁要給別人看時，丟一條大約一小時後會消失的連結。
先在自己電腦看過，再決定要不要丟臨時連結。這份說明頁放在 explainer-hub。
02

類比

用家裡修線路來對，下面會標哪裡不像
這套做法像家裡修線路：有人排工、有人動手、有人在岔路指路，最後交一張你看得懂的說明紙
牆上的工作板，今天修哪一段 ↔ ORCA
拿工具、真的去改線路的人 ↔ Pi Agent
岔路前說「走左邊還是右邊」的人 ↔ Jev
畫給屋主看的說明紙，不是線路本身 ↔ html-visualizer
把說明紙貼上公佈欄，約一小時後撕掉 ↔ cfdrop
類比在哪裡失準： 指路的人不會拿起工具；說明紙不是牆裡的線路，看懂紙不等於線路已經正確；公佈欄會自己收掉，它不是家裡的檔案櫃。

誰做什麼

上面是我讀到的，下面是工作怎麼被排開
我讀的那層 html-visualizer 畫成說明頁；要外傳才加上 cfdrop 給人看
判斷 Jev 只在岔路回答：換，或不換 不改檔
動手 Pi Agent 讀程式、改檔、跑指令 會改檔
工作台 ORCA 接上各助手，每一輪放在自己的工作桌 編排
四件事分開，我就不會在同一個視窗裡同時追「做到哪」「該不該換」「這段到底在講什麼」。判斷不取代動手，說明頁也不取代程式本身。
04

ORCA 這兩週對我最有感的兩件

手機可以接著做，同時進行的開發也不搶同一份檔案
1 · 手機
人在外面，先登入自己的帳號。
2 · Relay
把這次操作送回我家的電腦，不是把整台電腦公開出去。
3 · 家裡的 ORCA
Mac 或 Mac mini 上的那份接著跑。
4 · 助手
Claude、Codex、Cursor、Grok、OpenCode 各自登入後接上來寫。
第一件有感是：助手不用都擠在我眼前這台電腦。手機下指令，活是在 Mac 或 Mac mini 上做的。我離開座位，這一輪還可以繼續。

為什麼同時開發會打架

大家擠在同一份資料夾
專案通常只有一個打開的位置。甲要換分支，乙眼前的檔案會整份被換掉。改到一半的東西會互相蓋。
同一專案，各一張工作桌
worktree 是再開一個資料夾，帶自己的分支。甲改功能 A，乙改功能 B。兩份檔案分開，所以不會被對方的切換抽走。

工作桌和看板不是同一件事

看板 workspace。把好幾張工作桌排在一起看：哪一台機器、哪一輪、做到哪。我從手機看到的是這一層。 在看
工作桌 worktree。同一個專案的另一個資料夾，自己的分支。真正把檔案分開的是這一層。ORCA 可以很快建好，不用我自己複製一整包再記住哪個資料夾安全。 在寫
主資料夾 平常那一份留著。不拿來讓兩個人輪流切分支。 別動
一張工作桌同時只給一個在寫的人。看板可以把很多張桌子排在一起看，不會把兩個人放進同一張桌子。桌子分開之後，做完仍要各自收進來，不會因為分開了就自動合併。
05

走一遍

這兩週典型的一次。不是某一份改動的逐筆記錄
1 · 我知道有東西在改，但看不懂
可能是一整包程式，也可能是助手剛解釋的一段。我要的是人話，不是再多一份清單。
此刻
我手上有的 看不懂的程式或長說明
我還缺的 改在哪、為什麼、哪裡別誤會
2 · ORCA 開一張工作桌，助手動手
這一輪放在自己的 worktree，不跟別人搶同一份資料夾。人在外面的話，手機經 Relay 也能叫 Mac 或 Mac mini 上的這一輪繼續。
此刻
工作桌 這一輪自己的資料夾
人在哪 電腦前，或手機遠端
3 · 岔路出現，先問 Jev
要不要換做法，不由動手的那個直接猜。Jev 給判斷，Pi 再照判斷繼續。
岔路的兩種結果
不換 沿原路線做完
要換 Pi 改走另一條 Jev 只判斷，不下手改檔
4 · 畫成一頁說明
html-visualizer 把這輪「誰做什麼、改了哪一塊」收成一頁。我先讀這一頁。
頁上會有的
誰做什麼 工作台、動手、判斷、說明
這輪結果 改了哪一塊、不要誤會成什麼
5 · 先留在自己電腦
看過、改過字，再決定要不要給別人。沒有網址也可以用。
此刻
檔案 在自己的電腦
網址 還沒有
6 · 要分享，才做臨時連結
cfdrop 給一條大約一小時的連結。時間到，連結就沒了。本機那份還在。
分享之後
連結 約 60 分鐘
不放上去的 學生資料、密碼、憑證
06

容易誤會的三件事

名字都很像「又一個會寫程式的工具」，其實分工不同
容易想成
Jev 也是一個會改程式的助手，跟 Pi 做同一件事。
實際上
Jev 只在岔路給判斷。改檔、跑指令的是 Pi。沒有判斷要換，Pi 就沿原路線繼續。
容易想成
說明頁做出來，就表示這份改動已經審查通過。
實際上
這一頁幫我讀懂。對不對，仍要看測試和本來的審查，不因為畫得出來就成立。
容易想成
cfdrop 就是我的網站，貼上去就一直在。
實際上
它是臨時連結，大約一小時後消失。連結還在的時候，拿到網址的人打得開。要留久，得另外選固定的地方。
07

邊界

這些情況不要把這套直接套上去
!
學生資料、密碼、憑證 不寫進說明頁，也不送去給 Jev 判斷。這頁只談工具怎麼分工。
!
說明頁不是正確性證明 它解釋「在做什麼」。程式對不對，要另看測試和審查。
!
臨時連結不能當講義 大約一小時就沒了。要留久，用本機檔，或改放固定的地方。
!
還不是所有開發的預設 這是這兩週的試驗。投影片、對外的研究報告，走原來的做法，不塞進這一頁。
!
Relay 不是公開遠端桌面 連的是我自己登入的 ORCA。分享串上的人拿到說明頁，不能因此操作我的 Mac。
!
工作桌分開，不等於已經合併 worktree 解決的是同時改檔時互相干擾。做完還是要各自收進同一條線，它不會自動合併。

想再看一層

主線到上一節就夠分享。這裡是我自己還在調的部分
為什麼要拆成四件事 原因

動手、判斷、解釋、分享如果擠在同一個視窗，我只看得到助手一直在講，看不出它現在是在改、在選路，還是在跟我說明。

拆開之後，我可以只看說明頁。想追進度再回到 ORCA。岔路的判斷留在 Jev，不跟改檔混在一起。

Pi 和 Jev 怎麼接 這兩週

Pi 負責執行。走到要不要換路線，把這個問題交給 Jev，拿回判斷再繼續。

分數門檻和每一條路線的細節，這兩週還在調，所以這頁不寫成已經定案的規則。

臨時連結和固定網站差在哪 分享

cfdrop 的臨時連結用新的臨時帳號，大約 60 分鐘，時間到就收掉。它不在我自己的固定站上。

想留久，可以改放固定子頁，或把 HTML 放進 GitHub。這份說明頁走的是後者，掛在 explainer-hub 的 GitHub Pages。
